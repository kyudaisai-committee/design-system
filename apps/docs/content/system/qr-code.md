QRコードの表示は、対象と日時を添えた**提示カード**を基本にします。上部の見出しと案内文は、用途に合わせて差し替え・省略できます。[提示カードの見本](/storybook/?path=/story/components-qrcode--default)は、上部の文章を付けない構成です。

## 上部の文章は、目的と提示方法を補うときに使う

| 項目                 | 役割                             | 表示例                                         | 省略できる条件                                     |
| -------------------- | -------------------------------- | ---------------------------------------------- | -------------------------------------------------- |
| 見出し `title`       | QRコードを何に使うかを示す       | 「受付用QRコード」「入場券」                   | 周囲の画面タイトルで用途が分かる場合               |
| 案内文 `description` | 誰に見せるか、どう使うかを伝える | 「受付スタッフに、この画面をお見せください。」 | 周囲に同じ案内がある、または提示方法が明らかな場合 |

どちらも任意の項目で、部品に固定の文章はありません。見出しだけ、案内文だけでも使えます。両方を省略すると上部の領域もなくなり、QRコードの画像から表示します。[文章の有無を比較](/storybook/?path=/story/components-qrcode--header-content)

提示カード上部の見出しと案内文は中央寄せにします。画像の下の対象名・日時・受付番号は、左寄せで各行の先頭を揃えます。

案内文には利用者が次にする行動を書きます。「読み取ってください」は他の端末でコードを読み取る場面に使い、受付で画面を見せる場面では、見せる相手を伝えます。案内文に受付済み・失効などの状態を混ぜず、表示できない理由は`message`で示します。

画面に表示する文章を省略しても、画像の読み上げ名`label`は必須です。対象名・日時・受付番号は画像の下の`details`に置き、コードの対象を判断できるようにします。

## 使う場面から表示を選ぶ

| 表示形式          | 向いている場面                             | 配置と特徴                                              | 選ぶときの目安                                       |
| ----------------- | ------------------------------------------ | ------------------------------------------------------- | ---------------------------------------------------- |
| 標準表示 `plain`  | 本文や既存カードの中にある案内             | 枠を付けず、見出し・説明・216pxの画像を縦に並べる       | 周囲の画面で対象や日時を示せるとき                   |
| 提示カード `card` | 予約、受付、本人確認などで画面を見せる場面 | 248pxの画像と、対象・日時・受付番号を一つの面にまとめる | 当日の提示画面の基本。コードの対象を取り違えにくい   |
| 横型 `compact`    | 別の端末へURLを渡す場面                    | 160pxの画像と、説明・URL・リンクを横に並べる            | 同じ端末から開くリンクも添える。狭い領域では縦に並ぶ |

画像の寸法は余白を含む表示の目安です。コードに含める情報量に応じて必要な大きさは変わるため、実際に使う画像と読み取り端末で確認してください。狭い画面では領域に収まるよう縮小します。横型で読み取りづらい場合は、提示カードを選びます。

標準表示は画面の余白を使い、提示カードは一つの対象に関する情報をまとめます。提示カードをさらに別のカードで囲まず、QRコードの用途と対象が最初に読めるように置いてください。共通の配色・文字・角丸は[システムのデザイン](./DESIGN.md)に従います。

## コードの周囲に白い余白を保つ

QRコードの画像は白地に黒の正方形とし、周囲に4セル以上の白い余白を含めます。セルはQRコードを構成する小さな正方形です。この余白は読み取りに必要で、画像を囲むカードの余白とは別に確保します。[DENSO WAVEの余白の説明](https://www.qrcode.com/en/howto/code.html)

暗色テーマでも画像の白地を保ち、反転・半透明化・切り抜きをしません。角丸や境界線は画像の外側の面に付けます。コードにロゴや文字を重ねる装飾は、共通の表示には含めません。

URLを開くコードには、同じページへのリンクを併記します。読み上げ名は「九大祭公式サイトを開くQRコード」のように目的を含めてください。受付で使うコードには、読み取れない場合の案内や受付番号をテキストで添えます。認証用の秘密値を読み上げ名や補足に含めないでください。

## 読み込み・エラー・利用できない状態を区別する

| 状態          | 表示と操作                                                             |
| ------------- | ---------------------------------------------------------------------- |
| `ready`       | QRコードの画像と補足、リンクなどの操作を表示する                       |
| `loading`     | 画像を表示せず、「QRコードを読み込んでいます」と伝える                 |
| `error`       | 画像を表示せず、失敗の説明と、利用側が用意する再読み込み操作を表示する |
| `unavailable` | 画像を表示せず、期限超過・取消などの理由と次の行動を伝える             |

利用できないコードを薄くしたり、説明を重ねたりして残すと、読み取れてしまう場合があります。利用できないときは画像を取り除きます。画像自体の読み込みに失敗した場合もエラー表示に切り替わります。対象と補足はどの状態でも残します。

`QrCode`は生成済みの画像を表示する部品です。コードの生成、期限、受付済みかどうかの判定は、利用するシステムで行います。日時や受付結果の確認を、表示部品だけで済ませないでください。[画面と操作](./patterns.md)

## Webとアプリに組み込む

Webは`src`、React Nativeは`source`で画像を渡します。`title`と`description`は任意の表示文、`label`は必須の読み上げ名です。`details`に対象や日時、`actions`に代替リンクを渡せます。`actions`は`ready`のときだけ表示します。

```tsx
<QrCode
  src={qrImageUrl}
  variant="card"
  title="受付用QRコード"
  label="予約受付用のQRコード"
  description="受付スタッフに、この画面をお見せください。"
  details={<p>受付番号 K-080</p>}
/>
```

画面の見出しと案内で用途・提示方法が伝わる場合は、`title`と`description`を渡さずに使います。

```tsx
<QrCode src={qrImageUrl} label="予約受付用のQRコード" details={<p>受付番号 K-080</p>} />
```

アプリではOSの文字サイズに合わせて説明を折り返し、文字が大きい場合は横型も縦に並べます。WebとアプリのStorybookでは、3つの表示形式と、読み込み・エラー・利用できない状態を確認できます。見本の画像はすべて九大祭公式サイトを開くもので、実際の受付には使えません。
