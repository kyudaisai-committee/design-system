---
title: 進行状況と履歴
description: 今どこまで進んだか、何が起きたか、いつまでに対応するかを伝える。
---

手続きの現在位置、過去に起きた出来事、期限や予定は、それぞれ分けて表示します。申請の詳細なら、上部に「審査中」を示し、その下に提出期限や審査の進行状況、過去の提出・差し戻しを配置します。

## 知りたいことに合わせて部品を選ぶ

| 利用者が知りたいこと             | 部品                                                                   | 表示例                               |
| -------------------------------- | ---------------------------------------------------------------------- | ------------------------------------ |
| 今どこまで進んだか、次は何か     | [ProcessSteps](/storybook/?path=/docs/components-processsteps--docs)   | 提出 → 審査 → 審査結果               |
| いつ、誰が、何をしたか           | [Timeline](/storybook/?path=/docs/components-timeline--docs)           | 第1版の提出、差し戻し、第2版の再提出 |
| いつまでに、いつ行われたか       | [DateDetails](/storybook/?path=/docs/components-datedetails--docs)     | 提出期限、提出日時、通知予定         |
| 現在の状態だけを知りたい         | [StatusBadge](/storybook/?path=/docs/components-statusbadge--docs)     | 一覧の「審査中」                     |
| なぜ止まっているか、何をすべきか | [Notice](/storybook/?path=/docs/components-notice--docs)と関連する操作 | 不足資料の説明と再提出ボタン         |

ProcessStepsは順序が決まっている手続きに使います。順不同で行える作業はタスク一覧、並列の審査は担当別の表示にします。ファイル送信のように量を測れる処理には、[Progress](/storybook/?path=/docs/components-progress--docs)を使ってください。

## 現在の段階を薄い背景と文字で示す

現在の段階だけに薄い中立色の背景を置き、段階名を太字にします。横並びでは下辺、縦並びでは左側の線も使います。「審査中」「要修正」などの状態名を表示し、読み上げでも現在位置を伝えます。

背景の既定は中立色です。成功・注意・失敗を表す色と競合せず、現在位置を強調できます。[背景の比較](/storybook/?path=/story/components-processsteps--current-background-comparison)で情報色を使った場合と比べられます。完了した段階や次の段階まで背景を塗りません。

段階名は「提出」「審査」のように短くします。説明は修正する項目や操作の制約など、状態名だけでは伝わらない情報に限ります。「提出済み」に受付の説明を重ねたり、待つよう促す文章を足したりしません。説明が長い場合や段階が多い場合は、広い画面でも縦並びを選びます。Webの横並びは表示領域が40rem未満になると縦並びに切り替わります。

アイコンは出来事の意味に合わせます。「提出」は進行状況でも履歴でも同じアイコンを使い、完了したという理由だけでチェックに置き換えません。現在位置や結果は文字でも伝えます。

Webでは各項目の`icon`にLucideアイコンを指定できます。Nativeは`circle`・`edit`・`upload`・`search`・`check`・`undo`・`clock`・`flag`の固定セットから選び、各項目の`icon`に指定します。たとえば「提出」は`upload`、「審査」は`search`を使います。NativeのStorybookでは、進行状況の3段階それぞれと、履歴の先頭のアイコンをControlsで変更できます。省略時のNative表示は、進行状況では段階番号、履歴では点です。進行状況のControlsで「既定（番号）」を選ぶと、番号表示に戻せます。

## 分岐する結果を一列に並べない

承認、差し戻し、却下は、順に通過する段階ではありません。最後の段階を「審査結果」とし、確定した結果をそこに表示します。

| 場面                 | 進行状況の表示                                               |
| -------------------- | ------------------------------------------------------------ |
| 審査中               | 「審査」を現在の段階にし、「審査結果」は結果待ちにする       |
| 承認・却下で終了     | 「審査結果」を完了にし、結果名を添える。現在の段階は設けない |
| 差し戻し後の修正待ち | 「修正・再提出」を現在の段階にし、「再審査」を次に置く       |

「完了」は段階が終わったことを意味します。承認か却下かは、結果名と色で別に示してください。差し戻し前の提出や審査は履歴に残します。

## 履歴は、起きた出来事を順に並べる

Timelineには、提出、差し戻し、再提出などの出来事を日時とともに並べます。Web・Nativeとも、各出来事のアイコンや点を一本の縦線でつなぎます。「第1版を差し戻しました」「第2版を承認しました」のように、見出しで出来事を伝え、担当者、提出版、理由を添えてください。

現在の状態は、履歴の上に一つのバッジで表示します。Web・Nativeとも`currentStatus`に`{ label: "承認済み", tone: "success" }`のように指定します。途中の出来事には状態バッジを置きません。Webの`metadata`は担当者などの補足に使います。Nativeの既存の`statusLabel`は読み上げの履歴説明に残りますが、画面に出す現在の状態には`currentStatus`を使ってください。

古い順か新しい順かを決め、見出しの近くに表示します。現在の状態は配列の先頭・末尾や日時から推定しません。通知の送信や担当変更が最後に記録されていても、それが現在の審査状態とは限らないためです。並び順を変えても`currentStatus`は同じ値を渡し、現在の状態が分からなければ省略します。将来の予定は出来事の履歴に混ぜないようにしてください。

出来事の発生時刻が不明な場合は、画面を開いた時刻で代用せず「時刻の記録なし」と記載します。時刻を表示する場合は、日本時間などの基準も示してください。

## 期限と予定は、関係する段階に添える

提出期限・提出日時は「提出」、通知予定日は「審査結果」に添えます。画面幅や並び方が変わっても、この対応を保ちます。

期限は、その対象に適用される現在の期限だけを表示します。延長した場合は太字にし、「延長済み」と添えます。変更前の期限や標準期限は進行表示に並べません。

| 項目     | 表示例                     |
| -------- | -------------------------- |
| 提出期限 | 10月20日 17:00（延長済み） |
| 通知予定 | 未定                       |

表示に必要な期限データを取得できない場合は、画面全体を取得エラーに切り替え、再読み込みの操作を示します。既知の期限で補ったり、一部を「未確認」として進行状況や提出操作を表示したりしません。[期限データの取得失敗](/storybook/?path=/story/components-processsteps--missing-deadline-data)

期限を持たない手続きや、通知予定がまだ決まっていない場合は別です。予定が決まっていなければ「未定」と表示し、取得失敗や「期限なし」と区別します。予定日を過ぎても、自動で実績や完了に変えません。提出期限を延長しただけで、審査や通知の予定をずらすことも避けます。

## 読み込みや更新の状態を伝える

取得中は読み込んでいることを示し、失敗した場合は説明と再試行の操作を表示します。まだ結果を取得していない状態を「履歴なし」と扱わないでください。

更新時は「審査中」のように変更後の状態を短く伝え、読み上げで履歴全体を繰り返さないようにします。差し戻し理由や次の行動は、すぐに消える通知だけに置かず、画面に残します。

引数と使用コードは、各部品のStorybookを参照してください。
